## Entry points and contracts

Run `services.api:app`; `pipeline/07_pm_review_api.py` delegates to the same application. [BACKEND_RUNTIME.md](BACKEND_RUNTIME.md) documents startup and the tested runtime boundary. [OpenAPI](../contracts/openapi.json) and [the synthetic fixture](../contracts/fixture_case.json) describe the HTTP contract. Shared models include source/evidence, signal/draft, review, score, revision, audit and freeze contracts. Preserve original legacy payloads through the explicit import/reconciliation path; do not relabel legacy 0–10 scores as v1.

`GET /api/requirements` returns `{items,total,offset,ranking_id}` and caps each page at 200. Complete CSV/JSON export uses `/api/requirements/export`, independently of pagination. CSV maps actual backend names such as `finding_links` and `evidence_links` into the required BMW columns while preserving original fields. Detail, evidence, history, history download, sources/records/pages, signal/thread review, run status, preview and freeze endpoints are provided. `API_PREFIX` changes the new-contract prefix; root aliases preserve selected legacy URLs, not every historical schema.

Every edit/decision/application requires an expected revision, named PM actor and nonblank rationale. Body and route IDs must match. Invalid domain inputs return 422, stale revisions/baselines 409, missing entities 404 and unavailable dependencies 503. Patches cannot change server-owned status, calculated scores or revisions. Edits/applications produce `PM_REVIEW` and clear approval and old overrides; application never grants approval. Approval requires human source, target/milestone and assumption confirmations, current verified evidence and cited strategic assessment. The named PM mechanism is a prototype identity input, not enterprise authentication.

Decision bodies distinguish override intent: omit `score_override` to retain the current override, send a number (including zero) to enable it, or send explicit JSON `null` to disable it and restore the calculated score under the record's policy. Actual changes record full before/after scores and refresh the ranking baseline.

Role 2 must supply `operator` on every SMART metric: `<`, `<=`, `==`, `>=`, `>` or `!=`. Ordered comparisons require a finite numeric target; numeric text remains text in persistence. Equality/inequality also support categorical acceptance targets with explicit units, test conditions and verification methods. The shared synthetic metric is `<= "2"` actions. Milestones do not require an operator. Historical/legacy payloads remain readable; approval and reconciliation revalidate the complete draft. These structural checks do not prove that a target or its proposed test method is appropriate; separate human review remains mandatory.

Freeze rechecks selected approved revisions and evidence, captures complete requirement/source/configuration/ranking/decision payloads, and includes the full audit prefix through its retained checkpoint. Missing reconstructable source snapshots block freeze. Engine-supplied assumption/target review states start pending; only explicit human review can establish acceptance/resolution. Later edits leave committed snapshots unchanged. The hash chain is tamper-evident relative to a retained checkpoint; checkpoint retention outside the database remains an operational responsibility.

## Adapter responsibilities

`create_app` accepts injected `evidence_provider`, `source_provider`, `engine`, `import_service`, driver and repository. `BACKEND_ADAPTER_FACTORY=module:function` loads a synchronous factory during lifespan, passing `driver` and `repository`; it returns a mapping of those four adapter components. Invalid factories fail startup rather than silently replacing integrations.

- Evidence: `resolve(draft)` returns verified/traceable flags, authoritative `score_context`, `evidence_context`, pinned `source_snapshots`, and `required_assumption_ids`. Counts must describe the actual issue/cohort, forecasts need sourced 2030 locators, and fixed normalization is stored in immutable baseline configuration. Required successor/powertrain proxy IDs must identify the specific assumptions the PM must accept. Generic unrelated assumptions do not satisfy that guard. Native studies require reviewed relevant mappings; opaque channel labels remain opaque.
- Generation/review: `analyze(scope)` produces validated drafts with stable semantic identity; `review(entity, question, prior_turns)` returns cited answers, visible tool records and optional allowed patches. Review citations must resolve to authoritative source references. Signal review uses the same injected engine boundary. Model calls run outside governance transactions.
- Import: `prepare_import(scope)` performs conversion, file/network reads and validation outside a transaction; `commit_import(prepared, *, tx, audit_sink)` uses only the supplied Neo4j transaction to write sources/consolidations and returns validated result/provenance snapshots. The callback may be retried by the Neo4j driver. Never open/commit another session or perform external writes in it. `audit_sink(action, entity_id, before, after, rationale)` accepts SOURCE_IMPORTED/SIGNAL_CONSOLIDATED and participates in the same ledger transaction. The backend records run completion and every complete returned snapshot not already represented by a sink event. Matching requires exact JSON values for all returned fields; extra emitted provenance such as run_id is allowed. Thin/different sink payloads cannot suppress the complete result event. Identical repeated sink events are deduplicated within the import, while changed payloads, revisions and rationales remain distinct. Legacy `import_data(scope)` is accepted only with the MemoryRepository test double; Neo4j rejects it before invocation. Source-provider reads and graph-reference verification have synthetic and isolated graph acceptance, but Role 1's actual graph schema still needs reconciliation.
- Progress: adapters may accept `progress_callback`; supplied stage/progress/cache-mode updates are validated. Background jobs support partial results, bounded analysis batches, shared admission and same-thread review serialization. Interrupted jobs recover truthfully as failed. Execution is in-process, not a durable distributed queue.

### Review output and previews

Role 2 returns `ReviewEngineResult`: nonblank `answer`, optional `citations`, `tool_records`, `patch`, `coverage_gaps` (nonblank strings), `model_metadata` and `prompt_metadata` (finite JSON objects). Missing optional fields default to empty collections/null for existing adapters. Unknown fields and malformed optional values fail the run without a successful turn. Include provider/model identifiers, prompt version and context hashes in the metadata objects as available; empty defaults mean metadata was not supplied, not that a live model was verified. The backend persists these objects with the turn and completed audit payload, and model/prompt metadata with the run. Adapter `patch` is the HTTP proposal's field diff; the plan's conceptual `proposed_patch` must be mapped to this field by Role 2.

Applied revisions include `revision_application`: turn/run IDs, base revision, complete stored proposed patch and PM-accepted patch. The immutable revision and `SUGGESTION_APPLIED` event protect this acceptance provenance. A later edit or decision clears the marker on the new revision; the application revision remains intact in history. Accepted patches may select a subset of proposed fields and adjust their values under normal draft/evidence validation.

`analyze(scope)` may return the existing bounded iterable of draft dictionaries, or an `AnalysisEngineResult` envelope `{drafts: [...], model_metadata: {...}, prompt_metadata: {...}}`. Envelope metadata defaults to empty objects, rejects unknown fields and nonfinite nested numbers, and persists with the analysis run and initial immutable requirement revision/`REQUIREMENT_DERIVED` event as `generation_metadata`. Each draft still validates independently, preserving partial-result reporting. Existing iterable adapters receive empty metadata; this does not establish a real provider/model/prompt version. Identical regenerated content does not produce another derivation revision merely because model metadata changes.

Frozen Markdown includes a readable executive summary, list ordered by the frozen baseline ranks, SMART details, source citations, score rationale, ECI/coverage, validations/assumptions and decision history. The complete JSON manifest occurs once; its code fence grows when source content contains backticks so embedded text cannot terminate the manifest.

`score_preview` retains its existing priority-result shape. `change_preview` adds proposed content, authoritative ECI (`new_evidence`), old/new score and ranks, rank movements, base revision/ranking ID, and descriptive unresolved checks. Human target/source confirmations and unresolved assumption acceptance remain required; a preview never grants review or approval. A review completed after a concurrent edit is retained with `stale=true`; its preview describes the original base snapshot and cannot be applied to the new revision.

`POST /api/scoring/preview` also accepts `{requirement_id, expected_revision, patch}` for the same complete change preview without writes. Invalid/missing expected revisions return 422; stale revisions or changed immutable baseline configuration return 409. The existing alternate-weight preview stays available. Proposed content follows actual edit/application semantics, retaining already resolved assumptions; applying clears approval and overrides and produces PM_REVIEW. Source/target confirmations must be supplied again on approval.

### Regeneration proposal lifecycle

Analysis runs return `pending_turn_ids` alongside requirement `result_ids`; both lists contain distinct IDs. Changed drafts preserve the current requirement/status and produce deterministic pending proposals without chat-thread allocation. Identical changed drafts reuse the same pending proposal across run retries. A discarded deterministic proposal remains historical and is not advertised as pending on subsequent identical reruns.

Regeneration resolves reviewed semantic identity across original legacy IDs and generated hash IDs. Reconciled approved/rejected records retain their original IDs and decisions; changed proposals point to that same record. Ambiguous identity aliases, reconciliation collisions and edits that collide with another semantic identity return 409 without writes.

Review threads have fixed entity scope, creator and creation time protected by `REVIEW_THREAD_CREATED` events, including convenience challenges. Linked turns must match that audited scope. Older prototype threads lacking creation events fail closed and require independently verified provenance reconciliation; generating trusted events from mutable thread copies is unsafe. Older applied turns likewise require the protected terminal application event described in ROLE03_REAUDIT.md.

`GET /api/requirements/{id}/proposals` returns paginated `{items,total,offset}` (optional `state=pending|discarded|applied`, limit at most 200); `GET /api/requirements/{id}/proposals/{turn_id}` inspects the full patch/base/run and dynamically derived `stale` flag without writes. Apply uses the existing guarded `challenge-applications` route. `POST /api/requirements/{id}/proposals/{turn_id}/discard` uses the same discard handler as contextual review turns. It requires named PM, rationale and the current expected revision, records an audited discard without a requirement revision, and permits stale-proposal cleanup against the current revision. Identical retries return the same discarded turn without events; changed actor/rationale/base retries return 409. Applied/read-only proposals cannot be discarded, and unrelated entity proposals return 404.

### Role 1 retrieval and import coordination

Role 1's retrieval adapter must expose `search_feedback(query, scope, limit=20)`, `get_source_record(record_id)`, `get_survey_facts(topic, scope)`, `get_sales_facts(scope, year=2030)`, `search_document_chunks(query, scope, document_kind=None, limit=6)`, and `get_comment_cohort_counts(scope)`. Role 2 consumes these interfaces for bounded retrieval; Role 3 consumes their authoritative results through `resolve(draft)` and wraps source browsing through `list_sources`, `get(kind, id)`, and `verify_reference`. POST `/api/evidence/feedback-search`, `/survey-facts`, `/sales-facts`, `/document-search`, and `/cohort-counts` delegate directly to the corresponding injected source-provider methods. Bodies accept `scope` (regions/derivatives/powertrains/signal_ids/topics), required query/topic as applicable, bounded limit, optional document_kind and sales year (default 2030). Existing `/api/source-records/{id}` resolves individual original records through `get("record", id)`. Missing retrieval capabilities return 503; malformed/nonfinite adapter results fail rather than being presented as data. Graph citation verification resolves either SourceRecord or DocumentChunk with exact source ID, immutable version and locator; missing or cross-label ambiguous IDs fail closed, and duplicate same-label source identities return 503. PDF chunks do not need a fabricated SourceRecord twin. Retrieval implementations are owned by Role 1, not added to backend services. Returned identities, original values/text, source versions/locators, applicability and explicit unknowns must reconcile with the shared evidence DTOs before integration.

The backend now supplies a shared transaction/audit-sink import boundary. Real graph tests cover source-node/audit/result rollback on injected audit failure and malformed adapter output, successful commit without duplicate source events, and rejection of unsafe independent-commit adapters. These tests use a synthetic transaction-aware source writer; Role 1's production adapter/schema and actual input conversion still require integration. Failed imports clear uncommitted source/result metadata from the durable failed run.

The default runtime has no production evidence/generation/import implementation. A configured provider key alone does not install one. Source queries assume the documented graph schema; an empty result is not proof that BMW sources were imported.
